# Fathom — Future Scope & Roadmap

## Current State (v0.1 — Demo Ready)

What works today:
- ✅ SDK decorator (`@fathom_trace`) for automatic span capture
- ✅ Async ingestion API with idempotent upserts
- ✅ 3-phase evaluation engine (tool check, semantic drift, judge summary)
- ✅ Interactive DAG visualization with React Flow
- ✅ Dual-mode view (Developer / Non-Developer)
- ✅ Time-travel rewind with input mutation
- ✅ Pre-seeded demo data (3 realistic AI agent runs)

## Phase 2: Self-Healing Nodes (v0.2)

### What It Does
When a node fails, Fathom's AI automatically tries to fix it — without developer intervention.

### How It Works
1. **Failure detected** → Evaluation engine flags a span (e.g., hallucination)
2. **Auto-diagnosis** → Judge analyzes the root cause: "The LLM prompt lacks grounding instructions"
3. **Auto-fix generation** → AI generates a corrected prompt/input
4. **Auto-rerun** → Rewind engine applies the fix and re-executes downstream
5. **Validation** → Re-evaluates the fixed output; if it passes, the fix is accepted

### User Experience
- Non-developer sees: "⚡ Auto-heal available" button on failed nodes
- One click → Fathom fixes the prompt and re-runs
- If fix works → "✅ Healed!" — no developer needed
- If fix fails → Escalate to developer (see Phase 3)

### Technical Requirements
- LLM API integration (GPT-4o-mini or open-source alternative)
- Prompt template for fix generation
- Confidence threshold for auto-applying vs. asking user approval

## Phase 3: Auto-Escalation & Developer Alerts (v0.3)

### What It Does
When auto-heal fails or a problem is too complex, Fathom creates a full incident report and emails it to the developer — with the exact root cause and suggested code fix.

### Incident Report Contents
- What happened (step-by-step trace summary)
- What was tried (auto-heal attempt details)
- Root cause analysis (which step caused the cascade)
- Suggested code fix (file, line, change)
- Link to the trace in the Fathom dashboard

### Technical Requirements
- Email service integration (SMTP / SendGrid / Resend)
- Incident report template engine
- Developer contact configuration per project

## Phase 4: Pattern Detection Across Runs (v0.4)

### What It Does
Instead of debugging one run at a time, Fathom detects failure patterns across hundreds of runs.

### Examples
- "Step `score_lead_with_llm` fails 23% of the time when input contains financial data"
- "Steps using `gpt-4o` have 3x higher hallucination rate than `gpt-4o-mini` for this task"
- "Monday runs fail 2x more than Friday runs (possible data freshness issue)"

### Technical Requirements
- Run aggregation queries (SQL GROUP BY on verdict, span name, kind)
- Time-series failure rate tracking
- Pattern summarization (clustering similar failures)

## Phase 5: Regression Test Auto-Export (v0.5)

### What It Does
Every resolved failure is automatically exported as a runnable test case, ensuring the same failure never recurs silently.

### How It Works
1. Developer fixes a failing span (via rewind or code change)
2. Fathom captures the "before" (failing input/output) and "after" (fixed input/output)
3. Generates a pytest/unittest test case:
   ```python
   def test_score_lead_no_hallucination():
       """Auto-generated by Fathom from Run #abc123, Span: score_lead_with_llm"""
       input_data = {"company": "NovaTech", "revenue": 5000000}
       result = score_lead_with_llm(input_data)
       assert "Fortune 500" not in result["reasoning"]
       assert result["score"] < 80  # NovaTech is Series B, not Enterprise
   ```
4. Exports to `tests/regression/` directory in the project

### Technical Requirements
- Test template engine (pytest format)
- Git integration for auto-committing generated tests
- CI/CD hook to run regression suite on every deployment

## Phase 6: Company Knowledge Base (v0.6)

### What It Does
Companies upload their domain-specific rules and facts. The evaluation engine and auto-healer use this context for more accurate diagnosis and fixes.

### Examples
- "Our sales teams are: SMB, MidMarket, Strategic (NOT Enterprise)"
- "Series B companies should be scored as MidMarket tier"
- "Revenue below $10M = SMB classification"

### Technical Requirements
- Document upload API (PDF, Markdown, CSV)
- RAG pipeline for knowledge retrieval
- Context injection into Judge and Auto-Healer prompts
